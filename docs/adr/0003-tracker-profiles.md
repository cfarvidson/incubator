# The Night Queue's tracker is picked per run by a Tracker Profile

Amends ADR-0002. There is still exactly one Night Queue per Night Run, but which tracker serves it is no longer fixed to Linear: a Tracker Profile in `incubator.config.json` names a tracker (`linear` or `github`), its clone roots, and a default Claude Profile, and a run works under exactly one profile (`--profile <name>`, or `defaultProfile`). This is the "per-repo GitHub queues" extension ADR-0002 anticipated, shaped as whole-queue profiles rather than per-repo mixing: at work the queue is the Linear workspace, at home it is a GitHub owner/repo scope, never both in one night.

Core only sees `TrackerPort`; the queue filter is the same everywhere (open, assigned to me, labelled `ready-for-agent`). Where Linear uses workflow states, the GitHub adapter uses labels: `in-progress` is the Claim marker (and its absence the not-yet-Claimed filter), `in-review` marks a finished Card, and a repo is onboarded once it has a `needs-info` label - the other labels the Runner writes are created on demand.
